# 대화형 기능 구현 (impl-with-ask)

바로 코딩하지 않는다. **탐색 → 질문 → 구현** 3단계를 반드시 따른다.

---

## Phase 1: 코드베이스 탐색

사용자 요청을 받으면 **코드를 먼저 읽는다**.

### 탐색 대상

| 대상 | 방법 | 목적 |
|------|------|------|
| 관련 타입/인터페이스 | `Grep`, `Glob` | 데이터 구조 파악 |
| 기존 유사 컴포넌트 | `Glob`, `Read` | 재사용 가능 코드 발견 |
| 프로젝트 패턴 | `Read` | 기존 컨벤션 파악 |
| import 경로 | `Grep` | 의존성 파악 |

### 탐색 원칙

- **넓게 탐색**: 요청한 파일만이 아니라 유사 기능이 이미 있는지 확인
- **패턴 파악**: 기존 코드가 어떤 패턴으로 구현되어 있는지 이해
- **병렬 탐색**: 독립적인 탐색은 `Task` 에이전트로 병렬 수행

### Figma URL이 있을 때

Figma URL이 포함된 요청이면 코드 탐색과 병렬로 디자인 정보를 추출한다:

1. `get_screenshot` — 전체 화면 스크린샷
2. `get_design_context` — 컴포넌트 구조, 색상, 간격 등 디자인 토큰

> **주의**: Figma에서 **알 수 있는 것** (레이아웃, 색상, 폰트) 과 **알 수 없는 것** (인터랙션, 데이터 출처, 애니메이션 타이밍)을 구분하여, 알 수 없는 것만 Phase 2에서 질문한다.

---

## Phase 2: 대화형 질문

탐색 결과를 바탕으로 `AskUserQuestion`을 사용하여 구체적 선택지를 제공한다.

### 질문 규칙

1. **한 번에 1~4개 질문** — `AskUserQuestion`의 questions 배열 활용
2. **선택지 2~4개** — 모호한 개방형 질문 금지
3. **탐색 근거 제시** — "~를 봤는데, A와 B 중 어떤 방식으로?" 형태
4. **모를 때까지 반복** — 1회로 끝내지 않고, 답변에서 새 질문이 생기면 추가 질문
5. **불필요하면 생략** — 코드 탐색만으로 명확한 것은 질문하지 않음

### 질문 카테고리

#### 1. 재사용할 기존 코드
```
"기존 CenterSwiper 컴포넌트를 재사용할까요, 새 카루셀을 만들까요?"
```
- 유사 컴포넌트가 이미 있을 때 반드시 질문
- AI가 가장 많이 틀리는 부분 — 기존 코드를 모르고 새로 만듦

#### 2. 데이터 출처
```
"히어로 데이터가 SDUI 스키마에서 오나요, 별도 API에서 오나요?"
```
- 데이터 형태에 따라 구현이 완전히 달라짐

#### 3. 인터랙션/동작
```
"배너 자동 재생이 필요한가요? 필요하면 간격은 몇 초?"
```
- Figma만으로 알 수 없는 동적 동작

#### 4. 구현 범위
```
"렌더러만 구현할까요, 에디터도 같이 만들까요?"
```
- 범위를 확인하지 않으면 과도하게 또는 부족하게 구현

#### 5. 타입/디자인 불일치
```
"기존 타입에 subtitle 필드가 없는데, 타입을 확장할까요?"
```
- 기존 코드와 새 요구사항 사이의 간극 발견 시

### AskUserQuestion 사용 패턴

```
AskUserQuestion({
  questions: [
    {
      question: "기존 CenterSwiper를 재사용할까요?",
      header: "카루셀",
      options: [
        { label: "CenterSwiper 재사용 (권장)", description: "기존 배너에서 사용 중인 카루셀" },
        { label: "새 카루셀 구현", description: "디자인에 맞춘 커스텀 구현" },
        { label: "FlatListPageSwiper", description: "단순 페이지 스와이프용" }
      ],
      multiSelect: false
    }
  ]
})
```

## Phase 3: 플랜 작성 및 구현

모든 정보가 모이면 `EnterPlanMode`로 전환하여 구현 플랜을 작성한다.

### 플랜 포함 항목

1. **수정/생성할 파일 목록** — 경로와 작업 내용
2. **구현 순서** — 의존성 기반 순서
3. **재사용할 코드** — Phase 2에서 확인된 기존 코드
4. **테스트 계획** — 관련 테스트 실행 방법

### 구현 후 검증

```bash
# 관련 테스트 실행
yarn test --findRelatedTests [변경된 파일]

# 린트/포맷 검증
yarn eslint --fix --cache [변경된 파일]
yarn prettier --write [변경된 파일]
```

## 워크플로우 요약

```
사용자 요청
  │
  ▼
Phase 1: 코드 탐색 (+ Figma 있으면 디자인 추출)
  │
  ▼
Phase 2: AskUserQuestion으로 선택지 질문
  │  ↻ 답변에서 새 질문 발생 시 반복
  ▼
Phase 3: EnterPlanMode → 플랜 승인 → 구현 → 검증
```

## 안티패턴

| ❌ 하지 말 것 | ✅ 대신 할 것 |
|--------------|-------------|
| 요청 받자마자 코드 작성 | 먼저 관련 코드 탐색 |
| "어떻게 할까요?" 개방형 질문 | 선택지 2~4개 제공 |
| 기존 코드 무시하고 새로 구현 | 유사 코드 찾아서 재사용 제안 |
| 한 번에 모든 것을 질문 | 답변 기반으로 점진적 질문 |
| 탐색 없이 추측으로 질문 | 코드를 읽고 근거 있는 질문 |
